Full-Stack Dashboard + Multi-Bot Runtime + SQLite + Prisma + Termux Android

1. PERAN DAN MISI

Bertindak sebagai Senior Full-Stack Engineer, Software Architect, Node.js Runtime Engineer, Telegram Bot Developer, Database Engineer, Security Engineer, QA Engineer, dan DevOps Engineer.

Bangun aplikasi full-stack bernama Telegram Bot Manager, yaitu panel web untuk membuat, menjalankan, menghentikan, memantau, dan mengonfigurasi beberapa bot Telegram melalui satu dashboard.

Project harus benar-benar berfungsi, bukan sekadar UI mockup atau prototype.

Pengguna harus bisa:

1. Membuka dashboard melalui browser.
2. Login dengan aman.
3. Menambahkan bot Telegram menggunakan nama dan token.
4. Memvalidasi token melalui Telegram Bot API.
5. Menjalankan bot menggunakan template engine bawaan.
6. Menghentikan, memulai ulang, dan menghapus bot.
7. Memantau status runtime dan log.
8. Mengaktifkan atau menonaktifkan fitur bot dari dashboard.
9. Mempertahankan data setelah aplikasi atau perangkat direstart.

Aturan utama: aplikasi harus kompatibel dengan Termux Android dan tidak boleh mewajibkan Docker, PostgreSQL, Redis, atau layanan database eksternal.

Gunakan SQLite sebagai database utama dan Prisma sebagai ORM.

Jangan hanya membuat rancangan. Implementasikan seluruh source code, konfigurasi, database bootstrap, testing, dokumentasi, dan workflow CI yang diperlukan.

3. PERSYARATAN KHUSUS TERMUX

Project akan dikembangkan dan dijalankan pada Android melalui Termux.

Larangan

- Jangan mewajibkan Docker atau Docker Compose.
- Jangan mewajibkan PostgreSQL atau database server eksternal.
- Jangan mewajibkan Redis.
- Jangan menggunakan systemd.
- Jangan mengasumsikan direktori Linux standar seperti "/var/lib".
- Jangan mengandalkan PM2 daemon sebagai satu-satunya mekanisme startup.
- Jangan menggunakan binary yang tidak kompatibel dengan arsitektur Android tanpa pemeriksaan.
- Jangan mengharuskan pengguna mengedit source code untuk menambahkan bot.

Target pengalaman pengguna

Instalasi dependency pertama kali:

npm install

Menyiapkan database dan memeriksa runtime:

npm run setup

Menjalankan aplikasi pada penggunaan berikutnya:

npm run dev

Setelah setup pertama berhasil, "npm run dev" harus otomatis:

1. Memeriksa environment.
2. Memastikan direktori data tersedia.
3. Membuat file SQLite jika belum tersedia.
4. Memastikan database dapat diakses.
5. Memeriksa status migration.
6. Memulai backend dan frontend.
7. Menjalankan bot supervisor.
8. Memulihkan bot yang dikonfigurasi untuk auto-start.
9. Menampilkan URL dashboard dan informasi diagnostik.

"npm run dev" tidak boleh menjalankan ulang proses setup destruktif.

Instalasi paket

Sediakan pemeriksaan runtime yang jelas. Jika ada dependency native yang tidak kompatibel, tampilkan pesan yang menyebut dependency, versi runtime, arsitektur, serta langkah perbaikan yang relevan.

Jangan diam-diam mengunduh atau menjalankan executable tidak tepercaya.

Jika memungkinkan, sediakan skrip bootstrap Termux opsional yang memeriksa ketersediaan Node.js dan toolchain yang dibutuhkan. Skrip tidak boleh mengasumsikan semua paket Android tersedia dengan nama atau versi yang sama.

8. BOT SUPERVISOR DAN MULTI-BOT RUNTIME

Supervisor bertanggung jawab mengatur lifecycle setiap bot.

State machine

Gunakan status:

- "STOPPED"
- "STARTING"
- "RUNNING"
- "STOPPING"
- "RESTARTING"
- "ERROR"

Pisahkan desired state dan observed state.

Desired state menunjukkan keadaan yang diminta pengguna. Observed state menunjukkan keadaan yang benar-benar diamati supervisor.

Operasi runtime

Implementasikan:

- Start.
- Stop.
- Restart.
- Auto-start.
- Graceful shutdown.
- Health monitoring.
- Heartbeat.
- Error recovery.
- Retry dengan exponential backoff dan jitter.
- Pembatasan percobaan restart.
- Pencegahan worker ganda.
- Penanganan token invalid.
- Pemulihan setelah server restart.

Long polling

Gunakan grammY long polling sebagai default.

Setiap bot harus memiliki lifecycle polling sendiri.

Tangani konflik "getUpdates" dengan baik.

Pastikan satu token tidak dijalankan oleh dua worker bersamaan dalam satu instance aplikasi.

Jika terjadi konflik polling, tampilkan status error yang dapat dipahami dan jangan terus melakukan restart tanpa batas.

Isolasi runtime

Jangan menyimpan seluruh worker secara permanen dalam satu array global tanpa cleanup.

Gunakan registry runtime dengan identitas yang stabil, lifecycle yang jelas, dan cleanup yang deterministik.

Untuk Termux, prioritaskan worker dalam satu proses Node.js terlebih dahulu apabila terbukti lebih kompatibel.

Jika worker terpisah melalui child process digunakan, implementasikan:

- Penghentian proses secara benar.
- Penanganan sinyal.
- Cleanup resource.
- Pengawasan proses.
- Pemeriksaan stale process.
- Validasi kompatibilitas runtime.

Jangan mengklaim crash isolation penuh jika seluruh worker masih berada dalam satu proses.

Jangan membiarkan worker mematikan proses API tanpa sengaja.

Batas platform

Jelaskan bahwa Android dapat membatasi proses latar belakang. Dokumentasikan bahwa aplikasi harus tetap berjalan di foreground atau menggunakan mekanisme Termux yang sesuai apabila pengguna ingin menjaga layanan aktif lebih lama.

Jangan menjanjikan bot akan terus hidup jika Android atau sistem operasi menghentikan prosesnya.

9. KEAMANAN TOKEN DAN AUTENTIKASI

Token bot adalah rahasia berprivilege tinggi.

Implementasikan:

- Enkripsi token menggunakan AES-256-GCM atau mekanisme authenticated encryption yang setara.
- Kunci enkripsi yang berasal dari secret eksternal, bukan disimpan bersama ciphertext dalam database.
- Penyimpanan kunci di environment lokal yang dilindungi atau mekanisme secret storage yang sesuai.
- Pemisahan konfigurasi rahasia dari konfigurasi umum.
- Rotasi kunci yang memiliki prosedur eksplisit.
- Masking token pada seluruh output.
- Penghapusan token yang aman dari alur penghapusan bot.
- Validasi session.
- Cookie "HttpOnly", "SameSite" dan "Secure" sesuai deployment.
- CSRF protection sesuai mekanisme autentikasi.
- Rate limiting.
- Input validation.
- Audit log.
- CORS dengan origin yang diizinkan secara eksplisit.
- Proteksi endpoint administratif.
- Pembatasan akses berdasarkan pemilik bot.

Jangan menggunakan token sebagai parameter URL.

Jangan menyimpan token di localStorage browser.

Jangan memasukkan ".env", database, backup, secret, atau log privat ke Git.

Jika kunci enkripsi hilang, sistem harus menjelaskan bahwa token yang tersimpan mungkin tidak bisa didekripsi. Jangan berpura-pura memulihkannya.

Jika aplikasi mendukung satu administrator saja pada versi pertama, tetap implementasikan autentikasi dan jangan membuat endpoint administratif publik tanpa proteksi.

12. STARTUP ORCHESTRATION

Buat startup manager yang aman dan idempotent.

"npm run setup"

Fungsi:

- Memeriksa Node.js dan npm.
- Memeriksa kompatibilitas Termux.
- Menyiapkan direktori data.
- Membuat environment development jika belum ada.
- Menyiapkan kunci enkripsi jika belum ada.
- Menjalankan Prisma Client generation.
- Menjalankan migration yang tersedia.
- Memeriksa koneksi SQLite.
- Melakukan smoke test database.
- Menampilkan ringkasan hasil setup.

Setup tidak boleh menimpa secret yang sudah ada.

"npm run dev"

Fungsi:

1. Memeriksa environment.
2. Memastikan direktori database tersedia.
3. Memeriksa Prisma Client.
4. Memverifikasi koneksi database.
5. Memastikan migration sudah diterapkan.
6. Menjalankan supervisor.
7. Menjalankan API.
8. Menjalankan frontend.
9. Menampilkan URL lokal dashboard.
10. Menangani Ctrl+C dengan graceful shutdown.

Hindari race condition saat dua proses bootstrap mencoba menjalankan migration secara bersamaan.

Gunakan satu entrypoint orchestration yang mengendalikan urutan startup.

Jangan membuat frontend, API, dan supervisor menjalankan bootstrap database secara independen.

Jika satu komponen gagal memulai, hentikan komponen lain dengan benar dan berikan exit code yang tidak nol.

Contoh scripts package.json

{
  "scripts": {
    "setup": "node scripts/setup.mjs",
    "dev": "node scripts/dev.mjs",
    "build": "npm run build --workspaces --if-present",
    "lint": "eslint .",
    "typecheck": "tsc --noEmit",
    "test": "vitest run",
    "test:e2e": "playwright test",
    "doctor": "node scripts/doctor.mjs",
    "db:backup": "node scripts/backup.mjs"
  }
}

Contoh tersebut adalah target scripts. Sesuaikan command workspace dan TypeScript agar benar-benar berjalan dalam konfigurasi final; jangan menyalin command yang menimbulkan pemanggilan script rekursif.
